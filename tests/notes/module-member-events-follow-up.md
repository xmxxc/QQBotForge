# 群生命周期审查修复验证

本报告对应代码修复提交 [`0996a56ca991fc9ec62bc1757383a247a9621691`](https://github.com/xmxxc/QQBotForge/commit/0996a56ca991fc9ec62bc1757383a247a9621691)，以该源码与本测试提交的 `tests/` 组合复现。

代码修复起点为 `c84a30114c67e4e63cb71e2eaf7a5a3a00bde94b`，测试修复起点为 `0f2ea57f0bfc3091a1f4eb08f65188b753acb29d`。Python 3.13 完整回归为 **499 passed**，Ruff 与 mypy 均通过；Python 3.11 相关用例为 **58 passed**。

## 回归范围

- 私聊、频道、好友及私聊订阅事件不受无关群屏障阻塞，覆盖 WS 和 Webhook。
- 无群 ID 的私聊按钮独立处理；明确为群场景但缺少身份的按钮仍等待该 Bot 屏障。
- 同群积压 256 个交互时，其他群按钮仍执行处理器并返回 ACK 7。
- 等待群屏障时 ACK 计时从接收开始，超时后只发送一次默认 ACK。
- WS 开始关闭时立即取消全部传输分发任务，再统一等待清理；即使普通回调仍在异步清理，此时解除群屏障或归还并发槽也不会执行待处理按钮或其 ACK。关闭完成后的排队计数与任务正确清理。
- 挂起单群回调，分别积压 100、1000、10000 条生命周期事件，比较同时存活任务数；
  释放后检查全部事件的顺序、独立投递标识和逐事件订阅结果。
- 生命周期积压期间，其他群、其他 Bot 的通知继续完成。
- 积压回执在显式取消、模块卸载、连接关闭和回调超时场景均得到可核验终态。
- 本项运行代码和独立测试的解释性注释及文档字符串采用中文。

## 已观察的前后结果

修复前两个隔离用例失败：私聊未分发，无关群按钮处理器未执行便收到默认 ACK 0。
修复后，两项均通过，按钮实际 ACK 为处理器设置的 7。

同群生命周期积压新增存活任务数：

| 排队事件数 | 修复前 | 修复后 |
| --- | --- | --- |
| 100 | 459 | 261 |
| 1000 | 2259 | 261 |
| 10000 | 20259 | 261 |

这些数字来自隔离测试，不是线上生产性能承诺。队列仍保存每条待处理事件及完成凭据，
数据占用随积压增长；本次限制的是调度任务增长，未引入丢弃事件策略或总内存恒定保证。

## 运行方法

完整代码树与本测试分支的 tests 叠加到临时目录后，运行：

```sh
pytest -q tests/core/test_group_lifecycle_isolation.py tests/core/test_group_lifecycle_subscription.py
ruff check .
mypy core web main.py
pytest -q
```

测试使用临时配置和平台／存储替身，经实际 WS 分发、Webhook、Application、
ModuleManager 和 PluginManager 接线。不会对真实 QQ 群制造压力流量。
上游 CI 所使用的测试版本与这里的独立测试组合应分开报告。

第二轮固定差异 Standards／Spec 审查发现同一关闭窗口，已用两项先失败后通过的回归修复；最小增量复核和最终完整验证已完成，当前无未解决的已确认发现。关闭期间新到交互的接收竞态也已补回归并修复；
256 个同群交互积压时，其他群按钮与私聊按钮均实际执行处理器并返回 ACK 7。

## 恢复任务首次运行前取消的回归

整体复审发现：恢复协程若尚未运行便被取消，协程内 `finally` 不执行，导致关闭后保留暂存事件与队列计数。新增参数化回归通过真实 WS 入站投递 100 条通知，分别覆盖恢复任务尚未运行和已经运行两条关闭路径；检查暂存清空、`join()` 完成、重复关闭安全，以及全部通知按序成功。

修复前 1 failed、1 passed；关闭统一等待后增加残留暂存兜底清理，修复后两项通过。增量复核并复跑原探针后，暂存事件和未完成队列计数均为 0。最终完整测试为 499 passed，Python 3.11 相关测试为 58 passed。
