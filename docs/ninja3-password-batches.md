# #77 批量选择与指定密码（本地预实施）

基于 #75 本地候选 `438c46a30ea09b3c606c0b11c7036734f1458dfc` 的独立分支实现；本地预实施、作者自查，待独立审查。未推送、未部署、未真实登录或改密。单账号任务的意图、执行权、暂停、回执与恢复规则见 [改密任务接线](ninja3-password-tasks.md)，批次不复制也不绕开它们。

## 入口

QQ（仅当前 Bot 主人，每条命令重新核对主人身份；频道不受理）：

| 命令 | 行为 |
| --- | --- |
| `忍3批量改密` | 默认不选择，只提示用法 |
| `忍3批量改密 名称1 名称2 …` / `忍3批量改密 全部` | 选择单个、多个或当前 Bot 本插件全部账号，每账号独立随机密码；返回批次编号。私聊列出名称，群内只回数量 |
| `忍3批量改密 名称… 指定 新密码` | 仅主人真实 C2C 私聊；群聊（含“指定”紧贴密码的写法）一律拒绝且不回显、不使用该输入 |
| `忍3批量确认 编号` | 由同一选择者确认，开始逐个执行 |
| `忍3批量任务 编号` / `忍3批量取消 编号` | 查看逐项结果（群内只给计数）／取消 |

名称以空格、逗号或顿号分隔；名称本身含空格或“指定”的账号请用后台。

后台（已登录且同源，`backend` 选择者；相对 `/api/ext/ninja3/`）：

| 方法 | 请求 | 行为 |
| --- | --- | --- |
| GET `password-batches[/{id}]` | 无 | 批次及逐项结果，不含密码或密文 |
| POST `password-batches` | `{"accounts":[id…]}` 或 `{"accounts":"all"}`，可选 `"password"` | 选择；空列表拒绝 |
| POST `password-batches/{id}/confirm` · `/cancel` | `{}` | 确认／取消 |

单账号入口 `password-tasks` 与 `忍3改密` 不变，仍拒绝任何密码参数；指定密码只经上述批次入口（单选也是一项批次），原有拒绝用例无需改变。

## 范围、确认与指定密码

- 选择时记录稳定快照：每项账号 ID、名称和账号记录摘要；“全部”是当次账号集合，之后新增账号不会进入。
- 确认在一个事务里复核：同一选择者、每项摘要未变、“全部”的账号集合未变，否则整批拒绝并要求重新选择。复核通过后批次原子转为 running 并写入批次执行令牌；重复确认（含并发）返回同一批次与既有子任务。
- 同一选择者对未变化账号重复同一随机选择，返回同一未确认批次。指定密码的选择每次是新批次（不保存可比对的密码摘要）。
- 指定密码先做与协议相同的格式校验（6–16 字符、无空白）；同一值只作用于本次确认的账号，逐项比较旧密码，相同的一项标记“指定密码与旧密码相同”且不开始，其他项继续。执行到该账号时 `PasswordTasks.confirm(new_password=…)` 再次核对。
- 指定值以 #75 的外部 Fernet 密钥封存在批次里（绑定 Bot 与批次编号），不存明文；最后一项交给任务、取消或中断后即删除。每个账号的待用值仍按 #75 固定在其任务意图中，重试／重启不更换，通知不会触发改密。密钥缺失时批次不开始任何账号。

## 执行与结果

- 批次只做局部顺序编排：逐个账号先 `select`（同账号已有活动任务——单任务、其他批次或将来的紧急任务——则记为“已有其他改密任务”并链接该任务，不再提交），把子任务链接写入批次，再 `confirm(expect_digest=选择时摘要, guard=批次仍在运行)`：批次执行令牌、running 与取消标记在子任务认领的同一事务里核对，被取消、中断或另一进程接管后不会再认领任何账号；账号在执行到它之前变化则记为未开始。等该账号工作协程结束再处理下一个。
- 每次写批次都比较批次执行令牌、running 状态与取消标记；取消、另一进程初始化或重启都会让旧编排器停止，不能再开始后续账号。
- 一项失败或未知后继续下一项，不自动重发；某一项的存储错误记为“未能开始”并继续，批次记录本身无法写入时尽量转为中断并照常尝试发汇总（存储恢复前由重启转中断）。逐项结果从子任务实时推导：成功、远端成功本地待完成、明确拒绝、执行中、结果未知（暂停）、尚未提交（暂停）、已放弃、已有其他任务、选择后变化、指定密码与旧密码相同、未开始。“已受理”不代表改密成功。失败项按单任务规则由主人重试、放弃或恢复。
- 取消：未确认批次直接取消；运行中批次把未开始项标记为未开始，当前账号按单任务取消规则（提交前取消为尚未提交，提交后为未知暂停）。
- 重启／重载：运行中批次转为 interrupted，未交出的账号保持未开始，不自动继续；已确认的子任务按 #75 规则恢复。旧批次编号仍指向原批次，确认它只返回该批次，不会成为新批次。
- 回执：每个子任务照常发送单任务回执；批次结束（含取消）另发一条私聊汇总，逐项列出名称与结果。通知状态记录在批次 `notification`（sent／failed／unknown／unavailable），失败不改写结果，后台可查。群内只给计数。

## 敏感输出边界

新增代码不把指定输入、密码、密文、Cookie 或令牌写入日志、异常、回复或后台响应；操作日志集合不记录批次。框架接收消息时的正文日志按现有约定另行评估：主人在私聊发送的指定密码可能出现在框架消息日志中，本票未改变，也不宣称全链无敏感日志。群内误发的指定密码已在群里公开，插件只能拒绝使用。
