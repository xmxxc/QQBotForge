# 忍者必须死3（#72 手动授权与群内文字查询）

规格 #71 的 01 票。完整安装 `plugins/ninja3/`，并启用“群状态”“黑白名单授权”两个模块；不需要“自助问答”或旧“账户共享”。数据在插件目录 `data/ninja3.db`，与旧插件 `account-sharing.db` 互不读取、不迁移、不删除，两个插件可同时加载。

## 一条可演示流程

1. 主人登录后台打开“忍者必须死3”，选择 Bot，添加群原生 ID 并勾选“开放本群”；新增账号，填写名称、登录账号、密码，勾选“启用”并在“开放群”填入该群。新群、新账号默认都不开放。
2. 主人在该群发送 `@Bot 授权 @成员`。插件只使用平台 `mentions` 中被 @ 成员的原生 OpenID 和事件所在群；手写名称、同时 @ 多人、只 @ Bot 或非主人发送都不授权。
3. 成员在该群发送 `账号列表` 看到名称，再发送 `账号 名称`，Bot 在群内公开回复名称、账号、密码，说明和地址为空时省略。

## 规则

- 授权：成员当前在群事实不可用时，主人这条群内命令作为依据调用群状态既有人工确认（来源 `owner_confirmed`，依据含消息 ID），再在授权模块写入消费方 `ninja3`、功能 `query` 的持续来源：资源范围 `all`、长期有效。同一 Bot、群、成员、入群周期已有同样来源时不重复新增。群状态恢复未就绪（`recovery_required`、`recovery_processing`、写入中）时只回复“授权待处理”，不确认、不授权。
- 范围：一次授权覆盖本 Bot、本群、本消费方当前及以后开放的全部账号；不跨 Bot、群或消费方，不影响旧 `account_sharing` 消费方。账号的 `open_groups` 是 QQ 群原生 ID，由本插件维护；授权模块资源的分类 `groups` 始终为空，避免分类授权被群 ID 扩权。
- 与授权模块的配置权：放行要求插件开放范围（群开放、账号启用并在该群开放）与授权模块当前判断同时通过，不一致时保持限制。成员的列表、查询（以及以后的按钮）只读授权模块，不声明、不同步、不修复策略。只有主人在本插件保存配置时同步：
  - 保存或删除账号：按既有声明接口注册消费方（已有主人策略不被覆盖），只在新建、删除或启用状态实际改变时同步这一个账号的资源项（ID 与启用状态），其他情况返回 `acl_sync.status=not_needed`，不写授权。其他账号在授权管理中的启停保持原样；主人在那里停用的账号，不会因为改密码、改说明或保存别的账号和群而恢复，要恢复须在本插件先停用再启用该账号。授权模块不可用期间新建的账号也须这样重新同步，删除的账号会留在授权模块里，但插件不会再查询它。
  - 保存或删除群：只把这一个群加入或移出 `query` 功能的群范围，保留策略类型、私聊开关、其他群、拒绝、来源、期限和其他消费方。
  - 同步先读本插件记录，最后读取授权模块当前状态再写入，两者之间没有等待；主人同时在授权管理所做的修改不会被覆盖。
  - 每次同步的结果和前后群范围（账号为前后启用状态）记入 `GET /api/ext/ninja3/operations`，并在保存响应的 `acl_sync` 中返回。授权模块不可用时记为 `unavailable`，查询保持关闭，之后再次保存即可同步。
  - 主人在“授权管理”收窄群范围后，查询、插件重载和授权模块重载都不会写回；`GET /api/ext/ninja3/status` 列出被授权模块限制的群和账号。再次在本插件保存该群（或账号），是明确的同步操作。
- 查询条件：群已开放、账号已启用且在该群开放、调用者本人当前有明确授权（拒绝、框架黑名单、到期、离群、事实待核验或恢复中均不通过）。无完整名册、无私聊绑定也可以群内回复；群回复公开可见，个人授权只控制谁能触发，不代表旁观者有资格，也不生成全员资格报告。
- 发送前：全部异步读取完成后，同步复查插件数据版本（任何账号或群写入都会使在途查询失效）、插件与授权模块实例、调用及查看决定（来源、拒绝、资源启停、群范围、群事实凭据和模块代际），通过后立即发送；否则回复“账号或授权刚刚变化，请重新发送查询”。后续的暂停／紧急状态应加入同一检查。
- 未授权：`账号列表` 和 `账号 名称` 在读取账号记录前就判定资格，被拒时不读取账密。开放群中一般无授权、待核验、离群和到期的调用，以及群事实不可靠（需恢复基线、群状态未启用）的调用，都会记录通知。同一 Bot、群、成员首次立即私聊主人，十分钟内后续尝试只累加次数。本次确实送达时回复“已通知主人”，合并或未送达时回复“已记录给主人”；群事实不可靠时回复以“暂时无法确认查询资格”开头。
  - 以下情形不通知：明确拒绝名单、框架黑名单（框架在插件前拦截）、插件未开放的群、授权管理未纳入范围的群（回复“本群未开放账号查询”）、授权管理中已停用的账号（回复“该账号暂不可查询，请联系主人”）。
  - 群状态处理中或写入中（可重试）只回复“暂时无法确认查询资格，请稍后重试”，不记录。
主人须先私聊 Bot 发送 `忍3` 登记通知地址；未登记、平台拒绝或结果未知时通知保留在后台“未授权查询通知”，可重试，重试不授权也不发账密。
- 管理：后台接口 `GET/POST/PATCH/DELETE /api/ext/ninja3/accounts[/ID]`、`GET/POST /api/ext/ninja3/groups`、`DELETE /api/ext/ninja3/groups/<群ID>`、`GET/POST /api/ext/ninja3/notices`、`GET /api/ext/ninja3/status`、`GET /api/ext/ninja3/operations`，均需框架后台会话，返回 no-store。接口不返回密码；同 Bot 账号名称不可重复，开放群须先添加。删除群同时从所有账号移除。撤权、拒绝、到期调整使用“授权管理”的 `ninja3` 消费方。
- 日志：新操作日志只记录 Bot、群、成员、账号 ID 与结果，不含密码。框架消息正文日志是否记录回复正文沿用现有约定，本插件不改变。

## 入群自动授权（#73）

后台群表单和群列表有“新成员入群自动授权”，默认关闭，只对开放群生效（`POST /api/ext/ninja3/groups` 的 `auto_grant`）。保存群时，开放且勾选才在授权模块为该群建立 `ninja3`／`query` 的入群规则，关闭开关、关闭或删除群都会移除规则；同步前后记入 `auto_grant_before/after`，`status` 的每群 `plugin_auto_grant`／`acl_auto_grant` 对照两侧，不一致列入 `restricted_by_acl`。“授权管理”只能关闭该规则，不能为任何消费方开启；主人在那里移除规则后，查询和重载都不会写回，再次保存该群才同步。

- 唯一自动路径：群状态在可信恢复基线下收到的 WS 原生 `GROUP_MEMBER_ADD`（见 `docs/adr/0001-native-join-admission.md`）。授权模块在该事件的群状态消费通知内新增来源：本 Bot、本群、`query`、本消费方全部账号（以后开放的账号也覆盖）、长期、不含管理权；写入完成后通知才结束，恢复才就绪。
- 拒绝、框架黑名单、授权管理未纳入范围的群都不建立来源；已有自动来源也照常被拒绝优先。
- 首次调用不授予，也没有“调用时自动授权”。没有自动来源的调用沿用上文的未授权通知规则。缺字段、迟到、同秒冲突、同 ID 冲突、新会话或重启后恢复不明时成员保持待核验，按“需恢复基线”通知。
- 退群立即使自动来源和在途决定失效；可信重新入群只建立新周期的新来源，旧来源不复活，重复补发的同一事件不重复授予，主人撤销后也不会补回。
- 自动来源只在原生入群依据当前时有效：重建恢复基线（新会话、失败、重启、群状态重载）后不再可用，即使平台核验该成员仍在群；须主人在群内“授权 @成员”，这会另建主人来源，不复用自动来源。授权模块或本插件重载不影响仍然当前的依据。
- 关闭开关只停止以后的入群授权；进行中的写入完成后才生效，已经建立的来源在“授权管理”撤销。

能力分层：QQ 官方提供入群事件；源码 WS 订阅位 `1<<25` 并经应用→恢复层→群状态→授权接线，由 `tests/bot_modules/test_ninja3_join.py` 从原始帧验证；本 Bot 实际是否收到该事件及其字段尚未在真实 QQ 核验。

## 验证

`tests/bot_modules/test_ninja3.py` 使用真实 PluginManager 同时加载旧账户插件与本插件、ModuleManager 加载群状态和授权、WSClient 原始生命周期事件、鉴权 HTTP 和临时 SQLite，只替换 QQ 发送端。覆盖两个 Bot 与两个群、@ 原生身份、非主人与伪造显示名、无名册群内回复、恢复屏障、拒绝优先、通知十分钟合并与后台待办、停用／关闭／移出范围／删除／离群，查询准备期间改密、停用、关群、授权管理收窄、撤权、拒绝、离群、授权模块重载和插件重载均不发旧内容；成员查询不改变授权版本，授权管理收窄在查询、插件重载、授权模块重载后保留，插件与授权模块须同时放行，通知例外与一般未授权分别验证。`tests/bot_modules/test_ninja3_page.py` 用真实 Chrome 驱动后台页面的新增、编辑、删除和被拒保存（没有 playwright 或 Chrome 时跳过），并静态检查表单控件不遮蔽表单方法。`tests/bot_modules/test_ninja3_join.py` 覆盖入群自动授权：两 Bot 两群、默认关闭、首次调用不授予、离群／重入／重复补发／主人撤销、拒绝与黑名单、其他消费方和群策略不受影响、缺字段／同秒／迟到／同 ID 冲突／新会话、慢消费者与同会话补发、写入失败与重载取消、决定前的关开关／关群／拒绝／拉黑、写入期间离群与关开关、群状态重载／模块重启／新会话后不复活、旧会话迟到回调和授权管理收窄；“重启”以同一进程内依次重载群状态、授权和插件（重新读盘、新代际）近似，未实际重启进程；页面回归另在真实 Chrome 中操作入群自动授权开关。未连接真实 QQ。
