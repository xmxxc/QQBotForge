# 忍者必须死3（#72 手动授权与群内文字查询）

规格 #71 的 01 票。完整安装 `plugins/ninja3/`，并启用“群状态”“黑白名单授权”两个模块；不需要“自助问答”或旧“账户共享”。数据在插件目录 `data/ninja3.db`，与旧插件 `account-sharing.db` 互不读取、不迁移、不删除，两个插件可同时加载。

## 一条可演示流程

1. 主人登录后台打开“忍者必须死3”，选择 Bot，添加群原生 ID 并勾选“开放本群”；新增账号，填写名称、登录账号、密码，勾选“启用”并在“开放群”填入该群。新群、新账号默认都不开放。
2. 主人在该群发送 `@Bot 授权 @成员`。插件只使用平台 `mentions` 中被 @ 成员的原生 OpenID 和事件所在群；手写名称、同时 @ 多人、只 @ Bot 或非主人发送都不授权。
3. 成员在该群发送 `账号列表` 看到名称，再发送 `账号 名称`，Bot 在群内依次公开回复三条消息：名称及非空说明／地址、仅登录账号、仅密码；三条均为纯文字，便于分别长按复制，说明和地址为空时省略。

## 规则

- 授权：成员当前在群事实不可用时，主人这条群内命令作为依据调用群状态既有人工确认（来源 `owner_confirmed`，依据含消息 ID），再在授权模块写入消费方 `ninja3`、功能 `query` 的持续来源：资源范围 `all`、长期有效。同一 Bot、群、成员、入群周期已有同样来源时不重复新增。群状态恢复未就绪（`recovery_required`、`recovery_processing`、写入中）时只回复“授权待处理”，不确认、不授权。
- 范围：一次授权覆盖本 Bot、本群、本消费方当前及以后开放的全部账号；不跨 Bot、群或消费方，不影响旧 `account_sharing` 消费方。账号的 `open_groups` 是 QQ 群原生 ID，由本插件维护；授权模块资源的分类 `groups` 始终为空，避免分类授权被群 ID 扩权。
- 与授权模块的配置权：放行要求插件开放范围（群开放、账号启用并在该群开放）与授权模块当前判断同时通过，不一致时保持限制。成员的列表、查询（以及以后的按钮）只读授权模块，不声明、不同步、不修复策略。只有主人在本插件保存配置时同步：
  - 保存或删除账号：按既有声明接口注册消费方（已有主人策略不被覆盖），只在新建、删除或启用状态实际改变时同步这一个账号的资源项（ID 与启用状态），其他情况返回 `acl_sync.status=not_needed`，不写授权。其他账号在授权管理中的启停保持原样；主人在那里停用的账号，不会因为改密码、改说明或保存别的账号和群而恢复，要恢复须在本插件先停用再启用该账号。授权模块不可用期间新建的账号也须这样重新同步，删除的账号会留在授权模块里，但插件不会再查询它。
  - 保存或删除群：只把这一个群加入或移出 `query` 功能的群范围，保留策略类型、私聊开关、其他群、拒绝、来源、期限和其他消费方。
  - 同步先读本插件记录，最后读取授权模块当前状态再写入，两者之间没有等待；主人同时在授权管理所做的修改不会被覆盖。
  - 每次同步的结果和前后群范围（账号为前后启用状态）记入 `GET /api/ext/ninja3/operations`，并在保存响应的 `acl_sync` 中返回。授权模块不可用时记为 `unavailable`，查询保持关闭，之后再次保存即可同步。
  - 主人在“授权管理”收窄群范围后，查询、插件重载和授权模块重载都不会写回；`GET /api/ext/ninja3/status` 列出被授权模块限制的群和账号。再次在本插件保存该群（或账号），是明确的同步操作。
- 查询条件：群已开放、账号已启用且在该群开放、调用者本人当前有明确授权（拒绝、框架黑名单、到期、离群、事实待核验或恢复中均不通过）。无完整名册、无私聊绑定也可以群内回复；群回复公开可见，个人授权只控制谁能触发，不代表旁观者有资格，也不生成全员资格报告。
- 账号有未解决的改密任务时暂停查询：成员只收到“该账号暂不可查询，请稍后再试”，主人可看到对应的“该账号正在改密（批量任务 编号），暂不可查询”（批次发起时使用批次编号，单任务使用任务编号）；两种回复都不包含登录名或密码。
- 发送前：全部异步读取完成后，同步复查插件数据版本（任何账号或群写入都会使在途查询失效）、插件与授权模块实例、调用及查看决定（来源、拒绝、资源启停、群范围、群事实凭据和模块代际）；否则回复“账号或授权刚刚变化，请重新发送查询”。后续的暂停／紧急状态应加入同一检查。
- 发送准备之后：账号列表和账密回复把同一检查作为框架公开参数 `send_check` 传给 `Sender.reply`。框架在 `before_send` 管道、HTTP 客户端准备、令牌锁等待与刷新全部完成后，紧挨每次消息业务请求之前同步执行；检查只作为调用参数传递，钩子改写或移除 `event`／数据不会丢失。变化时拦截（不进入业务请求），改发上述不含账号内容的提示；检查本身出错按已变化处理。已进入传输的结果未知（含 `-1`）不重发。
- 首发边界：最终检查与首次业务请求之间没有 await；取令牌的请求不算消息发送。令牌过期重试和网络重试前框架会再次检查，此时拦截表示此前已尝试、结果未知，同样不重发；网络发送与撤权不承诺原子。
- 读取最小化：`账号列表` 用 SQLite JSON 投影只取 `id/name/enabled/open_groups`，登录名和密码不进入插件进程；`账号 名称` 也先在投影中定位，调用和查看决定都通过后才读取该一个账号的完整记录。投影读的是同一行记录，没有第二份元数据，初始化、写入、删除、启停无需另外同步。
- 未授权：`账号列表` 和 `账号 名称` 在读取账号记录前就判定资格，被拒时不读取账密。开放群中一般无授权、待核验、离群和到期的调用，以及群事实不可靠（需恢复基线、群状态未启用）的调用，都会记录通知。同一 Bot、群、成员首次立即私聊主人，十分钟内后续尝试只累加次数。本次确实送达时回复“已通知主人”，合并或未送达时回复“已记录给主人”；群事实不可靠时回复以“暂时无法确认查询资格”开头。
  - 以下情形不通知：明确拒绝名单、框架黑名单（框架在插件前拦截）、插件未开放的群、授权管理未纳入范围的群（回复“本群未开放账号查询”）、授权管理中已停用的账号（回复“该账号暂不可查询，请联系主人”）。
  - 群状态处理中或写入中（可重试）只回复“暂时无法确认查询资格，请稍后重试”，不记录。
主人须先私聊 Bot 发送 `忍3` 登记通知地址；未登记、平台拒绝或结果未知时通知保留在后台“未授权查询通知”，可重试，重试不授权也不发账密。
- 管理：后台接口 `GET/POST/PATCH/DELETE /api/ext/ninja3/accounts[/ID]`、`GET/POST /api/ext/ninja3/groups`、`DELETE /api/ext/ninja3/groups/<群ID>`、`GET/POST /api/ext/ninja3/notices`、`GET /api/ext/ninja3/status`、`GET /api/ext/ninja3/operations`，均需框架后台会话，返回 no-store。接口不返回密码；同 Bot 账号名称不可重复，开放群须先添加。删除群同时从所有账号移除。撤权、拒绝、到期调整使用“授权管理”的 `ninja3` 消费方。
- 紧急模式：主人可发送 `忍3紧急模式`、菜单入口或后台 `GET/POST /api/ext/ninja3/emergency`；先持久化 fail-closed 状态，再把当前 Bot 本插件所有账号逐项交给改密任务。`POST /api/ext/ninja3/emergency/exit` 只退出模式，不改变未解决任务的暂停。重启保留状态，已完成的 `complete` 阶段保持完成，只有运行中的阶段标为 `interrupted`，不能自动重复改密；运行中任务阻止退出，群内进入和结果只私聊主人，非主人命令静默。`GET` 只返回阶段、账号引用和安全结果，不返回意图或密码。
- 日志：新操作日志只记录 Bot、群、成员、账号 ID 与结果，不含密码。框架消息正文日志是否记录回复正文沿用现有约定，本插件不改变。

## 验证

`tests/bot_modules/test_ninja3.py` 使用真实 PluginManager 同时加载旧账户插件与本插件、ModuleManager 加载群状态和授权、WSClient 原始生命周期事件、鉴权 HTTP 和临时 SQLite，只替换 QQ 发送端。覆盖两个 Bot 与两个群、@ 原生身份、非主人与伪造显示名、无名册群内回复、恢复屏障、拒绝优先、通知十分钟合并与后台待办、停用／关闭／移出范围／删除／离群，查询准备期间改密、停用、关群、授权管理收窄、撤权、拒绝、离群、授权模块重载和插件重载均不发旧内容；`tests/bot_modules/test_ninja3_send_gate.py` 使用真实 MessageSender、HookManager 管道、TokenManager 与 `_request`（仅替换外部 HTTP 客户端），在另一个 `before_send` 准备等待期间注入同样九类变化，验证账号列表和账密都不进入首次业务请求、无变化正常发送、更晚的 `before_send` 回调不能越过检查、检查出错拦截、结果未知不重发，以及列表不读取账密、查询只读取选中账号；成员查询不改变授权版本，授权管理收窄在查询、插件重载、授权模块重载后保留，插件与授权模块须同时放行，通知例外与一般未授权分别验证。`tests/bot_modules/test_ninja3_page.py` 用真实 Chrome 驱动后台页面的新增、编辑、删除和被拒保存（没有 playwright 或 Chrome 时跳过），并静态检查表单控件不遮蔽表单方法。未连接真实 QQ。

## 菜单与共享目录（#74，本地预实施）

在本插件已启用、允许该 Bot、插件与 ACL 都开放的群内，单独 `@Bot`、`@Bot 菜单`、直接 `菜单` 进入同一菜单；`账号列表`、`@Bot 账号列表`、菜单的“账号列表”按钮进入同一目录。非 @ 消息还必须通过框架 `non_at_message.enabled` 或群白名单。精确匹配命令，不占用普通聊天；私聊和未开放群的“菜单”保留 self_qa 路由。插件拦截器早于 self_qa，命中只回复一次；未开放群显式“账号列表”仍沿用原查询的拒绝提示。

普通成员（包括尚未授权者）的菜单只有“账号列表”，打开菜单不通知主人；主人另见“修改密码”“紧急模式”。两个管理动作当前均尚未交付，只给不可用提示，执行时再次核验当前主人和群范围，不进行游戏平台操作。

目录按插件启用／开放群及 ACL 当前资源查看决定共同过滤，只展示允许查看的名称。每页最多六个账号，附上一页／下一页；没有可用账号时不发目录。选中后按引用重新读取当前内容，`账号 名称` 文字查询继续保留。#85 F5 涉及的 ACL 停用资源名称在新目录中也会被过滤。

按钮只携 `n3:<随机引用>:<编号>`；文字选择为 `忍3选择 <随机引用> <编号>`，菜单中提供完整格式。普通按钮消息不附文字选择提示；编号包含当页账号与翻页／管理动作，按钮明确拒绝后用相同引用、编号和场景降级为纯文字并附文字选择提示；Markdown 关闭时直接提供文字选择。网络失败、5xx、空返回或异常均视为未知，不重发菜单或凭据。插件不改变底层网络对同一平台载荷的既有重试行为。

菜单引用只在当前插件实例内存中保存 Bot、群、五分钟到期时间和动作／账号引用；不保存生成者身份或账密，重载／重启后旧引用失效。群内其他人点击或发送完整文字编号时，只用该次原生事件的实际成员重新判断资格，不能借用生成者身份；跨 Bot、群、私聊和频道拒绝。原生回调还校验应用、场景、chat_type 和框架黑名单，ACK 只表示收到。

凭据、目录以及降级发送共用 `Ninja3.current()` 最终同步门，检查账号／群版本、当前插件启用与 Bot 绑定、ACL 当前决定（含事实、周期、黑名单、授权时限和范围），菜单选择再检查引用期限。门在插件最后一次 await 之后执行，并作为 `send_check` 在框架发送准备之后、每次业务请求之前再执行（见上文“发送准备之后”）；菜单、目录、凭据的三条消息、明确拒绝后的纯文字降级和管理动作提示都经此门，变化时拦截并改发不含账号内容的提示。目录只读取投影元数据，凭据仅在选中账号且查看决定通过后读取；三条凭据消息按顺序发送，任一条被拦截或发送失败就停止后续消息。首发边界、令牌刷新窗口与网络重试见上文；网络发送与撤权不承诺原子。后续 #75 的账号暂停和 #78 的持久化紧急状态必须接入这个门（须保持同步、不可 await，因为它也作为 `send_check` 运行），目录过滤也须使用相同可用性规则；本票没有添加默认成功的假状态接口。

#74 不包含后台页面变更；本分支已合入发送边界基础候选，其中带有 #72 已独立复核的页面 F1 修复（`129df14`）。本地实现和作者自查不代表前置通过或独立批准。
