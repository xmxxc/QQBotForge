# 三模块分阶段安装与旧数据兼容

当前基础交付对应 #19；完整产品行为按 #18 及 #19—#36 逐票验收。

## 独立安装

使用相同版本的框架，将所需目录放入 `modules/` 或 `plugins/`。每个目录必须完整复制，包括 `storage.py`，不能只复制入口文件。

- `modules/self_qa/`：通过模块管理器启用，公开静态回复接口无需授权目录。调用 `manage(bot, namespace, 'create', {'name':'帮助','kind':'text','target':'公开说明','keywords':['帮助']})` 保存规则，然后 `answer(bot, namespace, '帮助', send, allowed=True)` 回复。`allowed=True` 由调用者确认启用范围；当前基础接口不自动订阅消息。面向主人的独立配置与消息入口由 #28 完成。
- `modules/access_control/`：可单独加载和管理授权存储。当前真实成员事件尚未接入，敏感查询默认拒绝；人工核验不能打开事件接入标记。
- `plugins/account_sharing/`：主人账户 CRUD／私聊预览的存储不依赖其他目录。成员查询和关键词仍分别需要授权、问答的运行能力；依赖缺失时不能发送密码。

这里的安装独立性不改变消费方的授权责任。命名空间、Bot 原生标识、群成员和私聊身份须明确传入；字符串相同不能证明身份关联。

## 升级与恢复

数据路径继续由框架上下文 `get_data_path` 提供：

| 扩展 | 相对安装目录的路径 |
| --- | --- |
| 授权 | `data/access-control.db` |
| 问答 | `data/self-qa.db` |
| 账户 | `data/account-sharing.db` |

B01 不搬库、不重写记录、不生成新 ID，也不执行跨库迁移。每个库沿用 SQLite v1 的 `extension_records(bot, collection, id, payload)`；现有授权 schema 的兼容读取与重启待核验规则继续有效。旧路径可重复打开；SQLite 写入失败保留原记录，修复故障后可重试同一键。高于受支持版本的库会拒绝打开，不能通过修改版本号绕过。

实际升级由主人单独安排。停用扩展并确认连接关闭后，使用 SQLite 备份或停机一致性副本；运行时的 WAL／SHM 不可随意丢弃。先在临时副本核对账户稳定 ID、规则引用、来源、期限、拒绝、入群周期、绑定和待办，再替换目录。保留原目录与副本供回滚。备份与回滚均不能将旧“在群”记录直接当作当前资格；重启后须可靠核验，已撤销来源不得重建为有效授权。

## 自动证据及限制

运行 `python -m pytest tests/account_sharing -q`。独立安装用例只复制指定扩展目录与框架到临时目录，使用真实管理器启停／重载；静态回复验证到发送替身。旧格式夹具通过鉴权 HTTP、主人命令和公开资格接口验证读取、稳定 ID 更新、拒绝、重启、绑定／待办保留及失败重试。

这些用例不证明群状态／恢复接线或平台许可已完成。B01 未做浏览器、真实 QQ、真实成员名册或生产数据迁移。现有框架日志可能记录回复正文。
