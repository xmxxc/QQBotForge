# 账户共享扩展接入检查

交付包含授权、自助问答两个模块和账户共享插件，框架源码与起点 `3951d873d734eaed12ae150abbf3d20f80d1f999` 一致。当前分支保留 draft PR #15。

## 存储

`modules/access_control/storage.py` 随授权模块安装，由自助问答和账户插件复用；不增加第四个安装包，也不要求通过权限查询才能使用存储。每个扩展继续用已有 `ModuleContext/PluginContext.get_data_path()` 获取自己的数据库路径。数据库实现使用标准库 SQLite 和 asyncio，沿用原有表结构、Bot 分区及文件名，不依赖 core 中的私有连接池或执行器。未读取或修改运行实例数据。

## 现有接口及缺口

| 现有入口 | 能做到什么 | 无法保证什么 |
| --- | --- | --- |
| `core/module/manager.py` 的 `ModuleContext.register_hook()` 与 `core/module/hook.py` | 注册、消费扩展主动发出的命名 Hook | 原框架事件入口没有向这些 Hook 广播原生事件；单纯注册不会收到退群通知 |
| `core/plugin/_dispatch.py` 非消息事件快速路径与 `@handler(event_types=...)` | 插件启用且匹配未被前置处理器阻断时，可接收生命周期事件；该路径跳过普通消息黑名单/维护检查 | 使用后台任务运行处理链，未保证撤权先于并发查询；受插件启停、Bot 绑定和处理器顺序影响，不能作为模块独立的前置观察接口 |
| 同文件插件拦截器 | 观察进入普通消息完整检查链的事件 | 位于黑名单/维护检查之后，生命周期快速路径不执行它 |
| `core/network/websocket.py` READY/RESUMED 与断线处理 | 框架内部维护连接、恢复会话 | 没有现成的模块连接状态通知，也没有向扩展提供已处理补发事件完成的屏障 |
| 现有发送器成员/分页接口 | 平台许可齐备时可执行当前成员核验 | 返回空值不能证明退群；接口可能无权限，不能用查询代替可靠事件源或承诺原子查询与发送 |

保留原要求需要的接口是：可信原生生命周期事件前置观察（独立于插件过滤/启停，并在相关查询继续前使资格失效），以及可信连接中断/连续恢复通知（含补发处理完成边界）。本次不向框架添加这些接口。

## 等待选择的方案

1. **保留完整保证，等待框架提供受支持接口。** 若已有其他版本或正式接口，可在确认其契约后接入；本任务不修改框架。当前暂停成员敏感查询，保留主人管理、问答匹配和策略代码。事件接入及相关端到端能力保持未完成。
2. **明确调整验收，使用现有插件入口进行有限接入。** 可由账户插件转交生命周期事件，发送前增加可靠成员核验，无法核验则拒绝。限制是依赖插件运行、异步调度不能保证前置撤权、没有独立的连接连续性通知；成员接口许可不足时成员查询可能持续不可用。该方案不满足原“模块独立接线、已知变更先于查询”的全部保证，必须经用户同意修改验收后再实施。

尚未选择任何替代接入方案，也未加入额外服务、运行时替换框架函数或直接读取运行实例数据库。
