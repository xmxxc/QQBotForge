# 三模块接入与当前实现边界

目标行为以[总体规格](../specs/bot-modules.md)为准，状态见[进度](account-sharing-progress.md)，父规格 [#18](https://github.com/xmxxc/QQBotForge/issues/18)。本文区分当前证据与需要交付的接口。

## 单向依赖

群状态提供事实、完整性和连续性凭据；授权消费事实并返回资格、绑定上下文和全员报告；问答独立提供公开问答，受限规则按需消费授权；账户共享组合问答与授权。群状态不依赖上层消费者，授权不回调问答或账户业务。未来群管可同时消费群状态与授权。

## 安装与存储

当前问答和账户直接导入授权包的通用 SQLite 存储。B01 将解除这种安装耦合，使用既有上下文数据路径并验证旧数据库兼容。公开问答单目录可运行是明确验收条件。各模块独立启停、Bot 与消费方分区；不以复用存储为由附带授权业务依赖。

## 框架契约与接线

- 群生命周期订阅：已有公开 API v1 与原生事件投递结果，[契约](../module-group-lifecycle.md)。
- 连接事实：已有连接／会话查询与订阅，[契约](../module-connection-status.md)；连接通知自身不证明消费者处理完成。
- 本地处理与恢复：personal 已有订阅、确认、基线及依赖凭据机制，[契约](../module-recovery.md)。精确版本、来源支持和与其他接口的组合由 F01 验收。
- 群状态经 G03 使用已验收契约更新事实并通知授权；不能通过直接打开旧 `lifecycle_available` 或模拟 Hook 证明生产接线。

## 当前业务限制

当前授权 setup 只创建策略实例，尚未消费新框架契约；默认敏感成员查询仍返回 `event_integration_unavailable`。现有 86 项业务测试主要使用模拟观察源。群状态独立模块、普通问答独立入口、通用绑定迁移及全员证明接口都由新票完成。

普通公开问答不依赖授权；受限规则、委托管理和账户查询在所需依赖失效时停止相关操作。下层共同故障的影响按真实依赖报告，无关 Bot／消费方局部状态应保留。

## 发送保证

全员报告由授权提供，完整名册由群状态证明；账户插件不自行解析平台名册或授权内部快照。所有候选／按钮／最终派发重新检查当前事实、策略、内容版本和期限。保证针对本进程已知事实，不承诺平台未投递事件或查询与发送原子一致。

框架缺口单独在 main 修复后同步，业务在 personal 接入和验收。本轮仅更新规划。旧接入检查见[档案](../archive/account-sharing-v1/account-sharing-extension-boundary.md)。
