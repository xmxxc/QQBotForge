# 三模块与账户共享实施 worker 提示词

当用户明确启动新规划的实施时使用下列提示词。本次文档和票据发布只更新计划；授权范围以用户启动实施时的指令为准。

---

你是 QQBotForge 实施 worker。读取父规格 [#18](https://github.com/xmxxc/QQBotForge/issues/18)、所有相关子票正文／评论／原生依赖，以及仓库 AGENTS 和其指向的分支、领域与 tracker 约定。完整需求在父规格中；本地入口为[总体规格](../specs/bot-modules.md)、[账户业务规则](../specs/account-sharing.md)、[实施清单](../plans/bot-modules-tickets.md)和[进度](../plans/account-sharing-progress.md)。

## 1. 核对起点

核对实际 Git、工作树、未提交文件、远程 PR 和票据状态，保留已有用户与其他 worker 改动。扩展基于 personal，框架基于 main；修复与业务分开提交和 PR。历史账户实现与未提交框架工作是待核对基础，不从旧票的关闭推断验收。

核对既有授权与持续任务范围；未被本次用户指令包含的发布、合并、部署和运行数据变更留待单独安排。仅使用临时数据库、假身份和平台替身测试，不启动真实 Bot。

完成条件：当前实现、授权范围、真实依赖和下一张可执行票均有依据。

## 2. 按新依赖交付

选择阻塞条件已满足的未完成新票，优先群状态 → 授权 → 问答 → 账户共享。B01 是存储兼容先行票，F01 可独立核对已有接口。技术无依赖的公开问答分支保持独立，不人为依赖授权。

每张票先复用现有代码及已调研上游能力，再完成从真实入口到结果的切片：必要的数据、独立加载、接口、页面／命令与行为验证。按 implement 等适用技能工作。真实事件接线与算法模拟分别报告。

交付顺序为：兼容扩展／迁移 → 消费者改用新接口 → 旧通用代码归位；稳定 ID、原授权来源、拒绝、期限和成员周期保留。相关测试及要求检查通过后，按用户授权提交、推送及更新 draft PR／票据。子票全部验收满足且实现可追溯才关闭；父规格保留待最终审核。

完成条件：本票验收逐项有实现与证据，状态如实更新，再计算下一张可执行票。

## 3. 必须保持的职责

群状态只维护群事实；授权维护策略、绑定和资格；问答独立接收消息、配置规则和组织回复；账户只维护账户业务并组合接口。底层不依赖上层，插件不解析授权内部版本或平台名册。

公开问答可单独安装。受限规则及角色委托按需复用授权；依赖不可用时相关操作拒绝，无关公开问答继续。群状态和授权不提供账密。

成员原生身份、私聊、union 与 QQ 号分开。退群撤销相关明确来源，重入需重新授权；新成员不自动联系。查询失败不等于退群，重启和未知连续性需核验。

问答精确／包含／正则；先按当前权限过滤再排序。并列只展示有权候选，点击重查。受限群回复全员查看通过才群发，否则状态后私发；账户另需主人开启群发和全员调用／查看。私发失败不公开敏感内容。

## 4. 可续跑记录与最终交付

每票记录提交、精确框架版本、测试及下一步；区分独立安装、算法、实际事件接线、浏览器与真实平台核查。阻塞保持打开，继续已获授权的独立部分。以新父规格和新清单为当前来源，旧规划档案仅供迁移追溯。

最终分别演示群状态独立、授权独立消费、公开问答独立、受限问答和账户共享，包含两个 Bot／群与多个消费方。报告迁移证据、权限／故障隔离、旧菜单及事件失效、严格群发与私发降级。合并与部署按用户当次授权执行。
