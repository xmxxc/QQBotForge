## 3. 实施时始终遵循的业务约束

完整规则以父规格和子票为准，尤其要贯穿所有入口：

- 交付黑白名单授权模块、自助问答模块、账户共享插件。授权逻辑与退群撤权归通用授权模块；匹配归问答模块；账户与发送流程归插件。
- 默认群白名单，加群不自动授权、不主动联系。只有主人管理，获授权成员查询；绑定与授权分别记录，绑定不等于授予资格。
- 权限绑定 Bot＋群＋成员；直接/功能组/全部功能以及单账户/账户组/全部账户可明确组合；一次批量和持续授权各自保留来源。拒绝优先，所有数据按 Bot 隔离。
- 群身份、私聊身份、union 标识和真实 QQ 号分别处理。无法可靠验证时进入主人确认流程，不靠相同字符串推断身份关联。
- 退群后该群各授权来源都不能继续使用，其他群独立；重入需要主人重新授权。断线、重启、被踢或状态不明时按规格核验，不能把查询失败当作确认退群。
- 每个账户就是一个按钮，点击直接查询；文字、关键词、按钮、翻页及管理 API 使用一致的业务校验。交互回调须显式鉴权，ACK 与发送消息分开。
- 私聊查询私发。群内查询只有主人已允许群发、完整名单且全群所有成员都有调用和查看该账户的资格才群发，包含本 Bot 和其他 Bot。
- 群发不合格时，群里提示将尝试私发，再向查询者私发账密。私发失败报告真实状态并提供绑定引导，账密不作为失败回退公开。
- 群发失败给主人逐人原因；无法核验完整名单时明确报告此限制，不能用本地活跃成员或人数冒充全群。检测到成员或权限变化就让旧决定失效；不宣称平台支持原子快照或绝对实时。
- 自动恢复群发由主人选择，默认关闭；开启也须重新核验，模式恢复不会主动发送密码，主人主动关闭后不被反向开启。
- 使用现有存储与日志机制；先交付已批准的查询和管理功能。必要的通用接口调整随对应票实施，独立需求另行记录。
