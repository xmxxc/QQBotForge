# #75 第一阶段协议接线说明

协议层离线预实施，非完整交付，前置 #72 待通过。固定基线 `bcf2657cb2a1afe925eabfd232a52a7fb8656ce1`。本阶段只提供独立模块、假平台测试和来源原件，没有业务入口和持久化。

## 调用边界

`await change_password(ChangeInput(phone, area, old_password, new_password), before_submit=...) -> ChangeResult(stage, remote_status, error_code)`。

调用者必须先完成主人鉴权、Bot 与账号归属检查、普通确认、同账号串行及同意图去重，将新密码绑定同一操作编号并受保护持久化，暂停账号，再解析凭据调用协议。输入 repr 隐藏全部字段；结果仅含枚举，不含密码、身份、Cookie、令牌或服务端消息。不要对输入做 dataclasses.asdict、记录局部变量或原始 HTTP；内存不承诺安全擦除。协议不生成密码、不读写数据库、不决定恢复查询。

每次使用全新 AsyncClient／Cookie jar、固定 HTTPS 源站，动态读取 env.js，验证 backend/baseUrl 和密钥格式。所有请求禁止自动重定向，不带环境代理设置；默认 httpx 传输没有重试。测试可注入 AsyncBaseTransport、UTC 时间和随机字节，注入端必须同样不重试。AES-CBC/PKCS7、动态签名和实际发送的 JSON 字节按 #70 保留，签名 path 不含 `/api/web`。

登录成功后读取当前会话 userinfo。当前严格要求 `data.phone` 为 `+86 `、原手机号前三位、`****` 和末四位组成的字符串，例如 `+86 166****0000`；缺失、类型不符、前后缀不符或掩码位置不符都失败关闭。userinfo 的其他字段不参与身份判断，`data.area` 不要求存在。change 与 verify 共用这一检查，不能退回“登录 HTTP 成功即身份正确”。

## 提交与结果

`stage` 表示最后到达的阶段：prepare、config、login、identity、prepare_submit、submit。`before_submit` 在身份通过、请求构造完成后调用；任务层必须在其中将同一意图持久标记为“可能已提交”，写入失败抛异常就停止。完成后有一次取消检查，紧接着进入提交边界。一次调用至多一个 change_pwd POST，不自动重试，也不使用新密码登录验证。

| remote_status | 判据 | 任务层动作 |
| --- | --- | --- |
| not_submitted | 未进入改密发送调用，包括配置、登录、身份或提交前持久化失败 | 仍保持暂停；保留同一意图与阶段，再由任务规则决定后续 |
| reported_success | 改密 HTTP 200、JSON 对象、严格整数 code=100，且无验证码信号 | 仅提交本地正式密码；本地写失败只恢复本地，不能再改远端 |
| rejected | 改密 HTTP 200、结构有效、严格整数 code 非100、无验证码信号 | 保持暂停，保留待用密码与意图，不能自动重发 |
| unknown | 已进入发送调用后超时、取消、传输错误、重定向、非200、无效JSON/结构或验证码信号等 | 持久化未知并暂停；由 #76 核验，不能以重发改密来恢复 |

非100表示拒绝沿用 #70 业务码约定；非200响应即使带数字业务码也保守判为未知。`error_code` 是固定枚举。登录阶段的拒绝依然是 not_submitted。已解析的明确成功／拒绝不会因会话清理失败或取消而降为未知。远端成功与本地提交必须分别记录，协议结果不声称本地已保存。

原脚本同步 requests 只存在于原件中；应用实现使用原生异步 httpx，不占用后台线程、不阻塞事件循环。配置20秒/API30秒是网络分段超时，不是总任务期限。运行中的取消被转换为结果；提交后取消只能停止本地等待，不能撤回服务端请求。协程开始前取消、进程强杀、掉电可能根本没有返回值；重启必须依靠先写入的意图及“可能已提交”标记保持暂停，不能仅凭没有结果判未提交。上层 wait_for／timeout 也不可把超时直接翻译为“未改密”。

下一阶段在 #72 通过后安排：持久化受保护意图与固定随机新密码、账户暂停、同账户串行与原子去重、普通确认、重启恢复、远端成功后的本地提交、主人私聊／后台回执。通知失败不能丢任务；未知结果核验属 #76。不得仅凭本模块或本轮测试宣称 #75 完成或可批准。
