# 自助问答（独立安装）

对应 Q01 #28。只复制 `modules/self_qa/` 完整目录，在模块管理中启用“自助问答”即可使用公开文字问答；不需要群状态、授权或账户共享目录。数据保存在该目录的 `data/self-qa.db`（SQLite v1 扩展记录格式）。

框架需要 `before_handler` 模块 Hook（框架 PR #47，`bf462cf`；业务验证组合为同步分支 `e501c95`）。该 Hook 在消息记录、用户追踪、黑名单、维护模式、非@群消息权限和插件拦截器之后、插件处理器之前执行。旧框架没有此 Hook 时，模块仍可作为匹配接口使用，但不会自动回复消息。

## 使用

1. 已登录后台打开“自助问答”，选择 Bot，填写启用的群原生 ID（每行一个），按需勾选私聊，保存启用范围。默认不启用任何群和私聊，不会向未知群自动开放。
2. 新增规则：名称、关键词（每行一个，行首 `#` 表示停用该关键词）、回复文字、匹配方式（精确／包含）、适用群（留空为全局规则）。可修改、删除规则，或停用规则。
3. 成员在启用的群里 @Bot 或在启用的私聊中发送关键词，收到回复。全局规则用于所有启用的群和私聊；分群规则只在所列群生效；私聊默认只使用全局规则（选定已核验群后的分群规则见 Q05）。未命中的消息不由问答回应，继续交给插件和框架默认回复。

主人 QQ 命令（群内只返回简短状态，私聊返回详情；普通成员发送不会处理）：

```text
问答管理 {"operation":"settings","groups":["群原生ID"],"private":true}
问答管理 {"operation":"create","name":"帮助","target":"公开说明","keywords":["帮助","说明"],"mode":"exact","groups":[]}
问答管理 {"operation":"update","id":"规则ID","keywords":["帮助",{"text":"说明","enabled":false}]}
问答管理 {"operation":"delete","id":"规则ID"}
问答管理 {"operation":"list"}
```

已鉴权 HTTP：`GET /api/ext/self-qa/?bot=...` 查看范围与规则；同路径 POST 上述操作对象，沿用后台会话，返回 no-store。

“公开”指在主人启用的范围内无需个人正向授权。框架黑名单、维护模式、非@消息设置及“忽略仅@其他 Bot／用户”照常生效。命中时问答回复并结束该消息的插件匹配和默认回复，因此同一消息不会被重复处理；框架消息日志和用户追踪仍然记录。

## 消费方接口

公开入口使用保留命名空间 `public`。插件按自己的命名空间调用 `manage(bot, namespace, ...)`、`match(bot, namespace, text, group=None)`、`best(results)` 和 `answer(bot, namespace, text, send, allowed=True, group=None)`。`group=None` 不按规则群范围过滤（由消费方自行决定准入），`''` 表示私聊只匹配全局规则。账户共享等消费方规则与公开入口互不匹配。逐规则权限与委托见下文 Q03。

## 正则、排序与多答案选择（Q02）

匹配方式：精确（默认）、包含、正则。保存时用 Python `re` 编译校验，每条最多 500 字符；无效时返回含错误位置的提示，原规则保持不变。后台“测试匹配”或 `问答管理 {"operation":"test","text":"价格9","group":""}` 返回全部命中（含排序依据）与最佳答案，不发送消息。

排序：精确优先于包含，包含优先于正则；同类按优先级（空为 0）；包含规则未设置优先级时较长关键词优先，显式相同优先级保持并列。全局与本群规则共同参与，不会自动遮盖；每条规则只出现一次（多个关键词视为别名），相同答案只保留一个。消费方可向 `match(..., admit=...)` 传入准入判断，未通过的规则在排序之前就被排除，并列菜单不会出现其标题。

正则在每个 Bot 独立的 `python -I` 工作进程中执行，单次消息 0.5 秒上限，输入最多 2000 字符。超时只结束该 Bot 的工作进程，相关正则视为未命中，其他规则照常回答，下一次请求自动重建；事件循环与其他 Bot 不受影响。

最佳答案唯一时直接回复；并列时回复候选标题列表（每页 5 个）和按钮。菜单只在当前进程内保存 15 分钟，绑定 Bot、提问者原生 ID、群或私聊上下文；按钮限定提问者（`list`），服务端仍再次核对。点击时先 ACK（状态码 0），再单独发送结果；按菜单中的原问题重新读取当前规则：规则已删除、停用、改范围或不再准入时提示失效，不回答。其他用户、其他群点击会被拒绝，不能借用原提问者的资格。平台拒绝按钮或关闭 Markdown 时改发同样内容的文字列表，用 `问答选择 <序号>`、`问答选择 页 <页码>` 选择；没有自己菜单的人发送该文字时交给插件与默认回复。

准备答案期间（如等待正则执行）规则或启用范围被修改、停用、删除或改适用群时，发送前的最终检查发现规则版本已变，不发送旧内容，而是按当前规则重新匹配（最多 3 次）；仍在变化时只回复“答案正在更新，请稍后重新提问。”。菜单标题和点击选择同样以当前规则为准。

## 逐规则权限与按群委托（Q03）

规则 `access` 为 `public`（默认）或 `restricted`。问答不保存名单、角色或授权；启用“黑白名单授权”后，问答自动注册消费方 `self_qa`：

| 功能 | 默认策略 | 用途 |
| --- | --- | --- |
| `public` | 公开 | 公开规则只检查明确拒绝与框架拒绝；不扩大问答启用范围 |
| `answer` | 明确授权，未启用任何群 | 受限规则默认策略，资源 `rule-<规则ID>`，查看动作 |
| `private-group` | 群成员，未开放任何群，允许私聊 | 私聊选定群后可使用该群规则的群（Q05） |
| `rule-<规则ID>-policy` | 主人设置 | 单条受限规则的群／成员／角色／明确授权策略 |
| `manage` | 群角色 owner/admin，未开放任何群 | 按群委托管理 |

主人操作（后台、私聊命令或 HTTP）：`{"operation":"rule_policy","id":"规则ID","policy":{"kind":"role","groups":["群"],"roles":["admin"]}}` 设置单独策略（`null` 继承 `answer`）；`{"operation":"delegate","groups":["群"]}` 开放委托；名单、授权、期限、拒绝在“授权管理”中对消费方 `self_qa` 操作。`list` 返回 `capabilities`，页面显示授权是否可用、受限与委托状态。

匹配时先按当前提问者资格过滤命中规则，再排序和组成并列菜单，无权规则的标题不会出现；选择时按点击者本人重新检查。受限答案在私聊按决定发送；在群里只有授权模块的全员资格报告（含本 Bot 与其他 Bot）确认全群都可查看时才群发，否则只提示“仅限有权成员查看”。等待全员报告等异步读取完成后，发送前先复查规则版本（存在、启用、内容、适用群、授权功能与启用范围，变化时按当前规则重新匹配并鉴权，见 Q02），再复查提问者决定；公开规则的决定同样复查（期间新增的明确拒绝会生效）。资格变化则提示重新提问。私发与跨群身份复用由 Q05 #32 提供。

委托：主人按群开放后，当前群主／管理员（群状态可靠角色）只能在该群用 `问答管理 <JSON>` 的 list/create/update/delete 管理适用范围恰好为本群的规则；新规则固定为本群、公开。群内 list 只公开本群公开规则的详情，受限规则只给数量（`{"rules":[…],"restricted":N}`），管理权不等于向全群披露。不能改全局或其他群规则、适用群、访问方式、授权策略、委托或启用范围，也没有后台入口。每次命令按当前角色重新判断，写入前在存储锁内复查决定，list 读取完成后、回复前也复查决定与模块状态，因此委托撤销、角色变化、角色未知或群状态／授权不可用都会使请求失效（无回应）。

授权模块不可用时：公开规则照常回答；受限规则不回答，委托暂停。

Q03 验证：群状态、授权、问答三个真实模块与插件分发器，原始 WS 连接与群状态事实，鉴权 HTTP 和群命令。覆盖受限规则排序前过滤、角色策略、全群查看报告前后的群发、明确拒绝优先、公开不扩大范围、授权停用、委托开放／撤销、普通成员／其他群／其他 Bot、越权字段与全局规则、写入前角色变化、群状态卸载。浏览器无可用实例，未做视觉核查；真实 QQ 与平台许可未核查。

## 图文、Markdown 与按钮（Q04）

规则可选：`format`（`text` 默认／`markdown`）、`image`（http(s) 图片链接）、`buttons`（最多 10 个，每个 `{label, action, value}`）：`link` 打开链接，`command` 填入查询指令，`rule` 回答另一条规则（填规则 ID）。后台“按钮”每行写 `标题|动作|值`。答案选择与翻页按钮沿用 Q02 菜单。

发送复用框架 `Sender.reply`（Markdown／键盘）和 `reply_image`（链接上传）。有按钮或 Markdown 且 Bot 开启 `message.use_markdown` 时先发富文本；平台明确拒绝时改发纯文字，按钮变成“链接：…”“发送「指令」”“发送「问答选择 N」”；图片上传失败改发图片链接。返回框架网络错误（code -1）、HTTP 5xx（无 JSON 正文时 code 为状态码）、传输异常或无结果时视为未知，不再重发答案、菜单或图片；只有平台明确拒绝才降级。每一段（富文本、文字降级、图片、图片链接）实际发送前都复查规则版本、提问者决定和全员报告：首段前已变化时按当前规则重新匹配，已发出部分后变化则停止后续内容并提示“答案已变化，其余内容未发送，请重新提问。”。`list` 的 `capabilities.formats` 显示该 Bot 的 Markdown／按钮配置和最近平台拒绝代码；未开启 Markdown 时直接发文字。框架在发送失败时可能另回 `api_error` 模板，这由框架设置决定。

规则按钮只携带会话引用（`qa:<会话>:r<序号>`），不含答案。会话绑定 Bot、提问者原生 ID 与群／私聊；点击时 ACK 后按当前存储重新读取目标规则（读取期间规则再变化则重新读取），再检查启用、适用群、问答启用范围与点击者本人资格（受限规则还需全群可见才在群里发送），因此修改后显示新内容，停用／删除／无权时提示失效。回复总是发到触发事件所在的群或私聊。

## 受限群回复转私发与私聊群上下文（Q05）

群里命中受限规则：先确认提问者本人当前资格（不合格或未知直接不回应，不透露规则）；再由授权模块的全员查看报告（完整名册，含本 Bot 与其他 Bot）决定。全员可查看才在群内发送；否则群内只给状态，答案通过授权模块 `member_context` 找到提问者经主人确认的私聊身份，`context_current` 复查后用 `send_to_user` 私发（富文本、按钮、图片走同一降级规则，规则按钮会话绑定到该私聊身份）。群状态只说明“已私聊发送／发送失败（平台代码）／结果未知／需先申请身份绑定”，从不回退群发答案，也不取消已有授权。群内并列菜单中不满足全员可见的受限标题显示为“受限答案”。

私聊命中受限规则：复用授权模块 `private_contexts` 的绑定与群选择。只有一个有效群时自动选择；多个群时提示 `问答群 <群ID>` 选择，`问答群` 清除选择（进程内保存）。公开私聊规则无需绑定。退群、角色变化、拒绝（含针对私聊身份的拒绝）、授权或群状态不可用、断线待恢复时受限答案即时停止；公开问答不受影响。

私聊群上下文与分群规则：私聊未选群时只匹配全局规则，不列出任何分群规则或标题。用户发送 `问答群 <群ID>` 后，只有当该群是主人开放的私聊群（`{"operation":"private_groups","groups":["群"]}`，即消费方 `self_qa` 功能 `private-group` 的群范围，默认不开放），且授权模块 `private_contexts` 确认该私聊身份经主人核实绑定到该群的当前成员时，该群规则才与全局规则一起参与匹配；去重、准入过滤与排序不变，受限规则仍按各自策略判断。随意填写未绑定、未开放或已退出的群 ID 只会得到全局规则。发送前与每段发送前复查该群上下文（`context_current`），等待期间退群或绑定变化时提示“资格已变化，请重新提问。”。群聊中的规则范围不变。授权模块不可用时私聊只匹配全局规则。

等待期间的变化：群内转私发在 `member_context` 等待后、私聊受限答案在 `private_contexts` 等待后，同样先复查规则版本（变化时按当前规则重新匹配），每段私发前再复查提问者决定与私聊身份；已私发部分后资格变化时停止其余内容，群内状态说明“已私聊发送部分内容”。并列菜单在检查受限标题（全员报告）后也复查规则版本，标题按当前规则显示。

委托 list 的受限详情：群内只给本群公开规则详情和受限规则数量；受限规则的标题、问法通过授权模块 `member_context`（功能 `manage`）确认的委托者私聊身份私发，`restricted_detail` 只说明“已私聊发送”、发送失败（平台代码）、结果未知或需先申请身份绑定，未确认送达不声称已发送。身份查询和私发前后都复查委托决定；委托撤销、失去管理员角色或模块重载后不再私发也不在群内返回详情。

Q05 验证：群状态＋授权＋问答真实模块、原始 WS 退群与断线后可信 RESUMED、主人确认绑定流程、平台替身私发（成功、平台拒绝、网络未知）。覆盖缺绑定引导、私发成功仅状态进群、发送失败报告代码且不群发、不合格提问者不回应、私聊单群／多群选择、角色变化、私聊身份拒绝、退群、另一 Bot、授权卸载、断线期间暂停、私发富文本与规则按钮再校验。真实 QQ 主动私聊许可与配额、浏览器视觉未核查。
