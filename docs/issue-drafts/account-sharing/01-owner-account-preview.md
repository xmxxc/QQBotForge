# 01：主人录入账户并私聊预览

GitHub 实施票：[#3](https://github.com/xmxxc/QQBotForge/issues/3)，父规格 [#2](https://github.com/xmxxc/QQBotForge/issues/2)。

## Parent

[账户共享管理需求规格](../../specs/account-sharing.md)。覆盖 R01—R04，并建立后续切片的最小业务入口。

## What to build

主人在已登录的 Web 扩展页新增、编辑、停用或删除一条账户，并通过主人私聊预览当前账号、密码。数据按 Bot 保存，重启后可继续管理。此阶段只开放主人管理预览，不把它作为普通成员授权查询的替代入口。

## Acceptance criteria

- [ ] 使用现有面板会话进入扩展管理页；未登录不能读取或修改账户，普通 QQ 成员不能执行管理命令。
- [ ] 支持账户稳定标识、显示名称、账号、密码、启用状态，以及可选说明、地址；主人可新增、编辑、停用和删除。
- [ ] 私聊预览读取最新值；停用或删除后不能经旧入口继续预览；管理命令与 Web 读写同一数据。
- [ ] 至少两个 Bot 的相同账户名互不串数据；持久化升级和重启保持结果一致。
- [ ] 复用现有扩展页面及鉴权路由，不要求重建主前端；加载、卸载和依赖不可用时反馈清楚。
- [ ] 管理页说明沿用现有消息及日志记录机制，不把发送成功等同于日志未记录。
- [ ] 提供可复用的事件、发送器和临时持久化测试宿主，验证完整管理到私聊预览流程，不访问真实 QQ。

## Blocked by

无，可开始。

## Verification

通过已鉴权/未鉴权 HTTP 请求和真实插件主人私聊入口，验证创建、修改、停用、删除、持久化及双 Bot 隔离。只替换平台接口，不针对内部表结构写镜像测试。
