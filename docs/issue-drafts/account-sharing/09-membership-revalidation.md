# 09：离线后暂停资格并由核验恢复

GitHub 实施票：[#11](https://github.com/xmxxc/QQBotForge/issues/11)，父规格 [#2](https://github.com/xmxxc/QQBotForge/issues/2)。

## Parent

[账户共享管理需求规格](../../specs/account-sharing.md)。覆盖 R16、R17、R24 的名册基础状态、R30 的核验结果。

## What to build

机器人重启、无法确认事件连续性的断线或被移出群后，相关授权进入待核验。接口可用时自动核验，否则主人通过 Web/命令单独或批量确认，恢复仍有效的授权。

## Acceptance criteria

- [ ] 持久化区分授权记录和成员核验状态，重启不能把旧记录直接视为当前仍在群。
- [ ] 无法确认事件连续性时暂停相关资格；只有能确认连续恢复的连接才可沿用状态，不能把重新连上等同于事件已补齐。
- [ ] 机器人被移出群时冻结该群资格，包括关联的私聊查询；重新加入后不能自动恢复旧授权。
- [ ] 成员查询无权限、网络失败和响应不明进入待核验，不当作确认退群；现有单成员封装返回空值不足以证明退群。
- [ ] 自动核验确认仍在群后，仅恢复未撤销、未到期且未被拒绝的授权；确认离开则触发模块撤权。
- [ ] 主人可从待办单独/批量核验，保存确认人、时间和结果；单人确认不会把全群名册标记完整。
- [ ] 名册同步完整遍历所有分页，独立保存本轮成员集合及完整性状态，不把历史合并表或群总人数当作完整快照。
- [ ] 同步中断、分页冲突或成员事件改变版本时保留不确定状态；不声称平台提供了原子快照。
- [ ] 后台显示哪些能力未开通、哪些状态待核验，以及可采取的处理；个人核验结果与全群完整性分别展示。

## Verification

模拟进程重启、可恢复/不可确认连续性的断线、被踢、接口许可不足、分页中断和混合批量结果，从私聊查询验证暂停与恢复。数据使用临时存储，不查询真实成员。
