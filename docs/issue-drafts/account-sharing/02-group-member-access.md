# 02：指定群成员授权并查看可用账户目录

GitHub 实施票：[#4](https://github.com/xmxxc/QQBotForge/issues/4)，父规格 [#2](https://github.com/xmxxc/QQBotForge/issues/2)。

## Parent

[账户共享管理需求规格](../../specs/account-sharing.md)。覆盖 R05、R06 的独立功能授权、R07 的单账户授权、R08 的基础拒绝、R10、R11、R13 的授权目标、R21、R29。

## What to build

主人为当前 Bot 设置账户共享的群白名单，指定群成员并授予单账户查询权限。成员在群里请求目录时，只能看到自己有权使用的账户。完成可复用授权模块的第一条端到端路径，初始目录可使用文字。

## Acceptance criteria

- [ ] 未配置白名单、非白名单群、无功能授权或无账户授权均不能获取账户目录及账密。
- [ ] 主人可通过群内 @成员、Web 已识别成员列表或明确标注类型的群身份指定对象；不把数字 QQ 号当作 OpenID。
- [ ] 授权绑定 Bot＋群＋群原生成员身份，其他群或 Bot 的授权不能串用；主人需确认当前成员状态或由可靠接口核验。
- [ ] 群白名单、个人直接授权、单账户资源许可、基础群/成员拒绝及解释结果由独立授权模块提供，不写成账户插件私有名单。
- [ ] 框架已拒绝的请求不能被插件重新放行；模块的明确拒绝优先于直接授权。
- [ ] 主人通过 Web 和命令完成白名单设置、授权及撤销，成员下一次请求立即反映变更。
- [ ] 新成员入群仅更新资格状态，不自动授权、不主动联系、不触发绑定；本地历史成员不冒充完整群名册。
- [ ] 未授权请求只在命中入口时给统一、限频提示；普通聊天不回应，不逐次私聊主人。
- [ ] 用另一个最小消费方验证授权模块不依赖账户数据类型；该消费方可在测试宿主中提供。
