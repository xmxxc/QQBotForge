# 11：群发失败显示逐人原因并可选自动恢复

GitHub 实施票：[#13](https://github.com/xmxxc/QQBotForge/issues/13)，父规格 [#2](https://github.com/xmxxc/QQBotForge/issues/2)。

## Parent

[账户共享管理需求规格](../../specs/account-sharing.md)。覆盖 R10 的全员解释、R26、R27、R30 的切换结果。

## What to build

主人在 Web 或命令中切换群发，失败时看到哪些成员不能使用及原因；配置是否在资格恢复后自动恢复群发，并能看清目标模式和实际模式。

## Acceptance criteria

- [ ] 切换时重新检查全员资格，失败保持实际私发；不存在忽略失败强制群发的入口。
- [ ] 私有报告显示账户、成员名称（如有）、准确身份标识、资格原因和对应处理入口；普通群消息只给状态，不公开整份授权资料。
- [ ] 明确区分无功能权限、无账户权限、拉黑、到期、成员待核验及名单不完整；不假造未识别成员或真实 QQ 号。
- [ ] 报告可处理真人及 Bot，不自动排除本 Bot；处理后重新核验，不以主人读过报告视为已解决。
- [ ] 自动恢复按群和账户配置，默认关闭；关闭时资格恢复仅通知主人，等待手动切换。
- [ ] 开启时资格重新核验通过才恢复；模式变化不主动发送密码，下一次查询仍须检查当前资格。
- [ ] 主人主动关闭群发清除恢复意向；后续资格恢复不能反向开启。
- [ ] 后台显示目标模式、实际模式、恢复开关、失败/待核验原因及最近操作结果；命令与页面修改同一配置。
- [ ] 重复检查、批量授权和重复成员事件不重复发送相同恢复通知，私聊主人失败时后台仍可查看。

## Blocked by

- [10：全员含 Bot 合格才群发，否则提示后私发](10-all-members-group-delivery.md)

## Verification

通过主人 Web/命令切换模式，再注入新增成员、授权补齐、拉黑解除和时间变化，验证默认手动、自动恢复、主动关闭和完整报告；不得通过管理请求参数绕过检查。
