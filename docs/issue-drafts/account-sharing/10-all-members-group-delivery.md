# 10：全员含 Bot 合格才群发，否则提示后私发

GitHub 实施票：[#12](https://github.com/xmxxc/QQBotForge/issues/12)，父规格 [#2](https://github.com/xmxxc/QQBotForge/issues/2)。

## Parent

[账户共享管理需求规格](../../specs/account-sharing.md)。覆盖 R23—R25、R28。

## What to build

主人开启某账户在某群的群发后，群内查询对当前完整成员集合逐一检查调用和账户查看资格。所有成员包含本 Bot 和其他 Bot 都通过才群发；否则群里先提示将尝试私发，再向已授权查询者私发账密。

## Acceptance criteria

- [ ] 群发资格按 Bot＋群＋账户计算，名单中所有成员都参与，不按 bot 标记、管理员或主人身份自动排除。
- [ ] 每个成员都通过相同的功能、资源、拒绝、期限和成员状态判断；Bot 也能作为明确授权对象管理。
- [ ] 每次实际群发前刷新完整名册、检查资格和版本；本地历史成员全通过、人数匹配或接口只有部分分页均不算通过。
- [ ] 没有完整名册接口许可、同步失败或状态不明时保持私发，向主人报告群发不可核验，不声称找齐了不合格成员。
- [ ] 收到新人、撤权、拉黑或期限变化后使旧群发决策失效；检查中发生已知变更时停止旧发送并重新判断或私发。
- [ ] 查询者个人资格不明则暂停查询；只有其他成员/完整名单影响群发时，已核验查询者仍可私发。
- [ ] 私聊发起始终私发；群内不合格时先发状态提示，再发送私聊；私发失败不在群里公开账密、不显示已送达。
- [ ] 同群账户甲通过不能让账户乙通过；没有主人群发许可时不自动公开发送。
- [ ] 可替换的文字/关键词/按钮适配共用同一发送决策，群按钮普通回复不能绕过路由选择。
- [ ] 实现与界面说明仅基于本轮核验和已收到事件判断，不承诺平台投递延迟期间已知成员变化。

## Verification

从查询入口覆盖全员通过、一个真人不通过、一个 Bot 不通过、名单不完整、处理中新人、查前/发送前撤权和私发失败；断言密码只进入最终允许的目标。无需等待按钮切片完成，使用同一公共查询入口验收。
