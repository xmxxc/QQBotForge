# 08：退群撤销全部授权来源且重入不恢复

GitHub 实施票：[#10](https://github.com/xmxxc/QQBotForge/issues/10)，父规格 [#2](https://github.com/xmxxc/QQBotForge/issues/2)。

## Parent

[账户共享管理需求规格](../../specs/account-sharing.md)。覆盖 R11、R15、R16；为后续群发资格失效提供成员事件。

## What to build

成员离开群后，由黑白名单授权模块撤销该群使用资格，所有消费功能即时受影响；重新入群保持未授权。通过最小通用生命周期接线把事件送入模块，不让账户插件自行维护另一套撤权逻辑。

## Acceptance criteria

- [ ] 主动退群和被移出均定位到 Bot＋群原生成员身份；union 显示配置不导致漏撤权。
- [ ] 直接、功能授权组、全部功能及持续资源授权都受当前入群周期约束，旧来源不能在重入后复活。
- [ ] 群 A 撤销不误伤群 B 的独立授权；黑名单记录保留。
- [ ] 收到入群事件不主动联系、不授权；先使相关全员检查版本失效，再执行可异步完成的历史记录持久化。
- [ ] 模块通过通用生命周期接线接收事件，普通消息白名单、黑名单、维护状态或账户插件不处理消息不能挡住撤权。
- [ ] 对重复事件、并发查询、已知的退群/重入顺序和重启后的持久化保证幂等；无法可靠区分迟到事件时暂停核验，不猜测恢复。
- [ ] 已知成员变更后未完成的查询不能按旧资格继续发送；测试控制交错顺序验证该边界。
- [ ] 主人可在成员管理页/命令查看已撤销及新的入群周期，并显式重新授权。
- [ ] 通用接线保持现有插件行为兼容，不依赖修复另行跟踪的插件文件禁用缺陷。
