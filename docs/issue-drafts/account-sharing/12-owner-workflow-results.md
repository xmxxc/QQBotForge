# 12：主人统一处理授权绑定待办并接收结果通知

GitHub 实施票：[#14](https://github.com/xmxxc/QQBotForge/issues/14)，父规格 [#2](https://github.com/xmxxc/QQBotForge/issues/2)。

## Parent

[账户共享管理需求规格](../../specs/account-sharing.md)。完成 R01、R10、R12、R17、R29、R30 的跨入口管理闭环和用户使用说明。

## What to build

主人在管理页集中查看并继续处理待绑定、待核验、群发检查失败和通知失败事项；QQ 命令可执行对应快捷操作，批量流程给汇总及逐项详情。完成从授权到点击账户按钮、退群撤权和群发恢复的整体演示。

## Acceptance criteria

- [ ] 管理页能按 Bot、群、成员和账户定位待办，直接完成绑定确认、有效授权核验、授权调整或重新检查，不需编辑数据库。
- [ ] 授权、绑定、核验、模式变更与消息发送有独立状态，批量操作展示成功、失败和待处理，部分失败可继续处理。
- [ ] 主人发起流程后向其已验证私聊身份通知结果；无私聊能力时后台留存结果、原群给简短状态，不能借用其他 Bot 发送。
- [ ] 通知关联原操作，重复事件和重试不产生重复成功通知；普通未授权尝试继续只限频提示，不逐次打扰主人。
- [ ] 普通用户不能读取其他人的授权、待办、逐人失败报告或调用管理接口；主人命令按当前 Bot 身份校验。
- [ ] 通过 Web 和命令完成同一管理流程，账户按钮和文字入口显示一致结果；不重建整个主前端。
- [ ] 提供面向主人和成员的使用说明，说明授权/绑定、私聊群选择、按钮降级、严格核验、包含 Bot 的群发条件、自动恢复设置和现有日志行为。
- [ ] 用两个 Bot、两个群及受控平台替身演示完整流程，记录真实平台按钮/名册/私聊能力的可选核查方法，不在自动验收中调用真实 QQ 或泄漏凭据。
