# 账户共享：核验、群发检查与待办

本页说明三个扩展中可独立使用的主人管理能力。框架源码保持原样，可靠事件接口由 [#16](https://github.com/xmxxc/QQBotForge/issues/16) 跟踪。成员敏感查询仍暂停，核验通过或开启群发意向都不能绕过这一限制。

## 成员核验与本轮名册

授权模块重新加载后，历史 `present` 成员进入 `pending`，已有来源继续保存。主人核实同一入群周期仍在群后，可恢复成员核验状态；不会增加授权、解除黑名单或延长期限。

```text
账户管理 核验 {"group":"fake-group","member":"fake-member","identity_type":"group_member_openid","confirmed":true,"state":"present","evidence":"已核实同一周期，期间未退出"}
账户管理 批量核验 {"group":"fake-group","confirmed":true,"state":"present","evidence":"已逐人核实同一周期","members":[{"member":"fake-member","identity_type":"group_member_openid"}]}
账户管理 自动核验 {"group":"fake-group","member":"fake-member"}
账户管理 同步名册 {"group":"fake-group"}
```

`POST /api/ext/account-sharing/access?bot=<AppID>` 使用对应操作 `verify/bulk_verify/verify_auto/roster_sync`。核验记录确认人、时间、周期和依据；Web 确认人固定为已鉴权面板管理员，QQ 使用当前 Bot 主人的原生身份，请求不能自行指定确认人。

`state:"absent"` 确认离群并撤销该群各来源。已经结束的旧周期不能经核验复活，应重新授权。批量逐项记录成功与失败，不回滚其他成功项。单人确认不会证明全群名册完整。

自动查询使用现有发送器的原始 `get_json`，检查原生身份和带时区的入群时间。API 无权限、网络失败、空值或不明响应均保留不确定状态，不能当作确认离群；若入群时间显示是新周期，旧授权退休，等待主人重新授权。自动核验需要手动发起，尚未接入连接恢复任务。

名册按 `next_cursor` 遍历全部分页，独立保存本轮集合，不合并历史活跃成员。重复成员、循环游标、缺少游标字段、分页中断或期间权限/成员版本变化，均不标记完整；最多遍历 1000 页，超过上限保留不完整状态。名册不自动授权或恢复其中任何成员。旧版本名册不能用于群发，平台未提供原子快照保证。

已知仍在群或刚加入的主体若缺失于平台本轮名单，同样保留不完整状态，要求重新核验。模块的可信适配入口 `suspend(bot, reason=..., group=...)` 可使指定群或整个 Bot 资格进入待核验；连接恢复本身不会撤销暂停。Bot 移出/重加入的状态机已通过模拟事件验证：撤销受影响群所有旧授权来源，冻结该群，重加入后需要重新授权，其他群独立。实际事件和连接通知尚未接通。

## 群发模式与逐人原因

```text
账户管理 群发 {"group":"fake-group","resource":"账户ID","enabled":true,"auto_restore":false}
账户管理 群发 {"group":"fake-group","resource":"账户ID"}
账户管理 群发 {"group":"fake-group","resource":"账户ID","enabled":false}
```

`GET /api/ext/account-sharing/group-delivery?bot=<AppID>` 列出设置；`POST` 与命令使用同形请求。页面使用上方群及选中的第一个账户。省略 `enabled` 是重新检查，`false` 清除群发意向；`auto_restore` 默认关闭。

目标模式和实际模式分别保存。发送前重新同步名册、逐人判断功能调用与账户查看资格，并确认本 Bot 的原生成员身份确实出现在名单中。其他 Bot 同样参与，不能按 Bot、主人或管理员标记排除。

报告只在已鉴权面板或主人私聊显示，包含已知名称、准确原生标识、调用及查看原因。名单不完整时明确报告限制，不声称已找齐所有不合格成员。缺少事件接口时实际模式保持私发，管理请求没有强制放行开关。

以下发送行为目前由模拟观察源验证，生产仍待接入：

- 全员合格且主人允许才群发，否则群内先提示再私发；私聊发起始终私发。
- 私发失败仅报告状态及绑定引导；已经尝试但未确认成功的群发不会自动向另一个目标重发。
- 关键词、文字和账户按钮共用查询路由；发送前重新检查版本、期限与已知变化。
- 关闭自动恢复时，后续重新检查发现资格恢复会通知主人，等待手动开启；开启时重新核验通过才恢复。
- 模式变化不会主动发送账密，主人关闭后不会因恢复检查重新开启。

框架黑名单、维护状态、身份显示设置与主人配置参与发送前快照校验。检查中发生变化会使旧结果失效。成员/授权变化和到期会使原群发模式失效；默认手动恢复不会因为后来权限已补齐而自行开启。普通消息补充同一原生身份的观察信息，不等于授权变化。

当前检查由主人命令、页面或查询发起。成员变更后的主动失效通知、连接恢复与后台检查依赖 #16，保持未完成；不能提前感知尚未投递的事件。

## 主人待办与通知重试

```text
账户管理 待办 {"group":"fake-group","member":"fake-member"}
账户管理 重试通知 操作ID
```

`GET /api/ext/account-sharing/tasks?bot=<AppID>` 可用 `group/member/resource` 筛选。待办包括待绑定申请、待核验成员、未达到目标的群发设置和失败/未发送的主人通知。页面“处理”定位到绑定、核验或群发区域，由主人确认具体操作。

`POST /api/ext/account-sharing/tasks?bot=<AppID>` 使用 `{"operation":"retry_notification","id":"操作ID"}` 重试通知。同一 Bot 内已成功并记录的通知不会因重复请求再发。结果通过当前 Bot 已观察并验证的主人私聊身份发送，不借用其他 Bot；私聊不可用时留在后台。平台结果不明、进程中断等情况下不能保证外部发送恰好一次。

授权、绑定、核验、模式、账密发送和主人通知保留独立状态；重试通知不会重新授权或发送账密。普通成员无法访问待办、绑定管理或逐人报告。

真实平台按钮、完整名册和私聊许可尚未验证。接口依赖完成后，可用单独测试 Bot、虚构账户及授权测试群核查：按钮是否被平台接受、名册是否能取完分页并包含本 Bot、已验证私聊身份能否收信；许可失败时核对文本降级、待核验和真实发送失败结果。自动测试不连接真实 QQ。

完整用法见[账户共享说明](account-sharing.md)，接入边界见[扩展接入检查](plans/account-sharing-extension-boundary.md)。
